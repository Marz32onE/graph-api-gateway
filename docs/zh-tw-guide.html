graph-api-gateway

HTTP 閘道：將 kube-state-graph 與 switch 兩個 Cytoscape 圖後端合併為單一 GET /v1/graph 回應。本文件為繁體中文完整開發與維運指南。

專案概述

graph-api-gateway 是用 Go 撰寫的 HTTP 閘道服務。客戶端只需呼叫閘道的一個端點，閘道會依序：

  1. 把查詢參數原樣轉發給 kube-state-graph（Kubernetes 狀態圖，主圖）；
  2. 從主圖中擷取所有 K8s node 的 data.ipaddress；
  3. 若有 IP，以單次 POST 批次查詢 switch 後端（網路交換機拓撲）；
  4. 依 IP 將 switch 的「影子節點」對齊到 kube 節點 ID，並改寫邊的 source/target；
  5. 合併兩張圖，回傳統一的 Cytoscape.js JSON 信封。
設計原則：無狀態、無快取、無部分成功——任一階段失敗即回傳 502/504，不會回傳「半套」圖。可觀測性僅採結構化日誌（slog）：預設 JSON，可透過 LOG_FORMAT=text 切換為 text；每個請求一筆 access log；無追蹤後端。

與姊妹專案 kube-state-graph 採相同目錄慣例與 OpenAPI（swag + Swagger UI，離線內嵌）工具鏈，方便在兩個 repo 之間切換貢獻。

架構與整體流程

系統元件

┌─────────────┐ GET /v1/graph?... ┌──────────────────┐ │ 客戶端 │ ─────────────────────────► │ graph-api-gateway │ │ (UI / curl) │ ◄───────────────────────── │ (本 repo) │ └─────────────┘ 合併後 Cytoscape JSON └────────┬─────────┘ │ ┌─────────────────────────────────┴─────────────────────────────────┐ │ │ ▼ ▼ GET /v1/graph?{rawQuery} POST /v1/graph [{"ip":...}] ┌──────────────────┐ ┌──────────────────┐ │ kube-state-graph │ │ switch backend │ │ (主後端) │ │ (交換機圖) │ └──────────────────┘ └──────────────────┘

請求處理順序（GET /v1/graph）

客戶端請求 │ ▼ [Middleware] Recovery → Request-ID → Access log → API-key │ ▼ ① withTimeout(KSG_TIMEOUT) → kube-state-graph GET /v1/graph?{轉發查詢} │ 失敗 → 502 / 504 / 499 ▼ ② pipeline.ExtractIPs(主圖) // 僅 type=="node" │ ├─ IP 列表為空 → 跳過 ③，switchGraph = nil │ ▼ ③ withTimeout(SWITCH_TIMEOUT) → switch POST /v1/graph body: [{"ip":"..."},...] │ 失敗 → 502 / 504 / 499 ▼ ④ pipeline.ReconcileSwitch(主圖, switch圖) // IP 對齊、丟影子節點、改寫邊 ▼ ⑤ merge.Merge(主圖, reconciled) // 節點 union by id，邊 dedup by (type,src,tgt) ▼ 200 JSON CytoscapeGraph

管線為循序執行（非並行）：switch 查詢依賴主圖擷取出的 IP，無法與主圖並行發起（除非未來做投機執行，目前不在範圍內）。

做了什麼

能力說明
圖合併將 K8s 狀態圖與交換機拓撲合併為單一 Cytoscape 信封，供前端一次渲染。
查詢轉發start、end、cluster、namespace、edge_type、name、root、depth、direction 等查詢參數原樣轉給 kube-state-graph。
IP 批次查 switch所有 node IP 打成一個 JSON 陣列 POST，避免 URL 長度限制。
ID 對齊switch 端點影子（如 sw-host:xyz）透過 data.ipaddress 對到 kube node ID（如 prod/abc），影子節點刪除、邊端點改寫。
健康檢查/livez 存活；/readyz 探測兩個後端 /livez 是否可達。
API 文件內嵌 OpenAPI 3.1 + 離線 Swagger UI（/docs/）。
日誌與認證僅結構化日誌：slog JSON/text（無追蹤後端）；可選入站 X-API-Key 認證。

刻意不做的事（v1）

  • 閘道本身不要求客戶端認證（僅轉發各後端的 X-API-Key）。
  • 無快取、ETag、重試。
  • 無部分成功（不會回 200 + warnings）。
  • 無 Prometheus /metrics。
  • 不支援第三個後端（架構預留擴充，但未實作）。

管線演算法詳解

階段 2：ExtractIPs

僅處理 data.type == "node" 的節點（Pod 的 IP 不會送給 switch）。對每個 IP 做插入順序去重，回傳穩定順序的 []string。

階段 3：Switch 請求格式

POST {SWITCH_GRAPH_URL}/v1/graph
Content-Type: application/json
X-API-Key: {SWITCH_GRAPH_API_KEY}   // 若設定

[{"ip":"10.0.0.1"},{"ip":"10.0.0.2"}]

階段 4：ReconcileSwitch

  1. 建立 ip → kube node ID 索引（主圖 node 類型）。
  2. 走訪 switch 節點：若任一 ipaddress 命中索引，記錄 switchID → kubeID 改寫表。
  3. 輸出新圖：刪除被對齊的影子節點；保留 switch 專用節點（chassis、port 等）；邊的 source/target 依改寫表替換。
  4. 若改寫後產生自環（兩個影子對到同一 kube 節點），該邊會被丟棄。

階段 5：Merge

  • 節點：以 data.id union；衝突時先寫入者勝（呼叫順序固定為 kube 主圖在前）。
  • 邊：以 (type, source, target) 去重，先寫入者勝。
  • clusters：各輸入圖的 clusters 欄位聯集後排序輸出。
  • 輸入圖不被修改；回傳全新結構。

資料模型要點（internal/client/backend.go）

NodeData.IPAddress 是 kube 與 switch 之間的唯一對齊鍵。switch 的端點影子必須帶 ipaddress，否則無法對到 kube node，影子會以原 ID 留在合併圖中（不會 crash）。

在 repo 根目錄執行：

# 下載模組 + 安裝主機端 dev 工具（golangci-lint、govulncheck）
make init

# 檢查工具鏈是否齊全
make doctor

# （可選）啟用 git hooks：pre-commit 快速檢查、pre-push 跑完整 CI
make init-hooks

make init 會執行 go mod download 並檢查 go.mod 是否 tidy。swag 透過 go.mod 的 tool 指令使用，無需另外 go install。

若 make doctor 顯示 golangci-lint MISSING，請確認 $(go env GOPATH)/bin 在 PATH 中，或再執行一次 make init-tools。

本地執行方式

依需求選擇下列其一或組合使用。完整管線行為由 internal/api/server_test.go 的 httptest 整合測試覆蓋；本地需連真實 kube-state-graph 與 switch，或僅預覽 API 文件。

方式 A：本機二進位 + 真實後端

當你已有可連線的 kube-state-graph 與 switch 服務時：

make build
# 產物：./bin/graph-api-gateway

export LISTEN_ADDR=":8080"
export LOG_LEVEL="debug"
export LOG_FORMAT="text"
export KUBE_STATE_GRAPH_URL="http://localhost:9001"    # 改成你的 URL
export KUBE_STATE_GRAPH_API_KEY=""                   # 若需要
export SWITCH_GRAPH_URL="http://localhost:9002"
export SWITCH_GRAPH_API_KEY=""
# 可選：export API_KEYS="secret-key-1,secret-key-2"  # 啟用入站 X-API-Key 認證

./bin/graph-api-gateway

或使用一行啟動（請替換 URL）：

KUBE_STATE_GRAPH_URL=http://ksg.example:8080 \
SWITCH_GRAPH_URL=http://switch.example:8080 \
LOG_FORMAT=text LOG_LEVEL=debug \
./bin/graph-api-gateway

如何新增或修改 API / 功能

以下依變更類型說明應修改的檔案與建議流程。變更後請執行 make test，若動到 HTTP 契約則執行 make docs 並提交產物。

新增或修改 HTTP 端點

  1. 在 internal/api/server.go 註冊路由
    例如 r.GET("/v1/foo", s.handleFoo)。Middleware 鏈已全域套用（Recovery、Request-ID、Access log、API-key）。
  2. 在 internal/api/handlers.go（或新檔）實作 handler
    參考 handleGraph：從 c.Request.Context() 取 context、用 withTimeout 包後端呼叫、用 writeFetchError 統一錯誤映射。
  3. 加上 swag 註解
    在 handler 上方撰寫 // @Summary、// @Router、// @Param 等（與現有 handleGraph 相同風格）。頂層 @title 等在 cmd/graph-api-gateway/main.go。
  4. 執行 make docs
    會產生 docs/swagger.{yaml,json} 並複製到 internal/api/static/openapi/。CI 的 docs-drift job 會跑 make check-docs，未提交會失敗。
  5. 補測試
    在 internal/api/*_test.go 用 httptest 驗證狀態碼與 JSON。現有 server_test.go 可作範本。

可觀測性

認證與可觀測性

  • 無追蹤後端；可觀測性僅採 slog 結構化日誌。
  • 可選入站 X-API-Key 認證；health（/livez、/readyz）、spec（/openapi.{yaml,json}）與 /docs/* 路由豁免。

Logging

  • LOG_FORMAT=json 適合生產；text 適合本地除錯。
  • 每個請求一筆 access log（method、path、status、duration_ms、request_id）。
  • /livez、/readyz 的 2xx 不寫 access log，避免探針洗版。
  • X-Request-ID：客戶端可傳入（需符合字元/長度限制），否則伺服器產生 UUID。

錯誤對應

情境HTTP回應
上游逾時（context.DeadlineExceeded）504{"error":"upstream_timeout"}
客戶端中斷連線499無 body（nginx 慣例狀態碼）
傳輸錯誤、非 2xx、JSON 解碼失敗等502{"error":"upstream_unavailable"}
就緒探針：任一本端後端不可達503純文字 not ready: ksg 或 switch

無重試：一次失敗即回錯誤給客戶端，不會回傳僅含 kube 圖的部分結果。

常見問題

啟動時報 KUBE_STATE_GRAPH_URL is required

兩個 *_URL 皆為必填。僅看文件時可用 make docs-preview 內建的 placeholder URL。

/v1/graph 永遠 502

  • 確認 KUBE_STATE_GRAPH_URL / SWITCH_GRAPH_URL 可從 gateway 程序連線（Docker 網路 vs host 網路）。
  • 確認上游有 /v1/graph 且 switch 接受 POST JSON 陣列。
  • 用 LOG_LEVEL=debug 查看結構化錯誤訊息（含上游 status 與 body 摘要）。

合併圖裡 switch 節點與 kube 節點沒連上

檢查 kube node 與 switch 影子是否都有相同 data.ipaddress。若 switch 未填 ipaddress，reconcile 不會改寫 ID，兩邊圖會並存但邊可能斷開。

主圖沒有 node IP，switch 會被呼叫嗎？

不會。ExtractIPs 為空時跳過 switch 階段，最後 Merge 僅輸出 kube 主圖（仍走 merge 以保持信封一致）。

make check-docs 失敗

執行 make docs，將 docs/ 與 internal/api/static/openapi/ 的變更一併 commit。

Go 版本與 Dockerfile 不一致？

go.mod 要求 Go 1.25；deploy/docker/Dockerfile 的 GO_VERSION build arg 預設 1.24，建置時可覆寫：docker build --build-arg GO_VERSION=1.25 ...。
